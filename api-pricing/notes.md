# 各家 LLM Provider 计费模型调研

> 调研日期：2026-06-25
> 核心问题：各 Provider 是怎么计算额度消耗的？是否区分输入/缓存/输出 token？
> 关联：[[llm-caching]] [[headroom]]

---

## 一、关键结论（先说结论）

**各家 Provider 的 API 计费都区分以下维度**：
1. **输入 token（Input）**：你发送给模型的内容
2. **缓存读取 token（Cache Read）**：从缓存中读取的输入部分
3. **缓存写入 token（Cache Write）**：首次写入缓存的部分
4. **输出 token（Output）**：模型生成的回复

**不同维度的价格差异巨大**：

| Provider | 普通输入 | 缓存读取 | 缓存写入 | 输出 | 缓存折扣 |
|---------|---------|---------|---------|------|---------|
| **Anthropic** | $3/M | $0.30/M | $3.75/M | $15/M | **90% 折扣** |
| **OpenAI** | $2.50/M | $1.25/M | — | $10/M | **50% 折扣** |
| **DeepSeek** | ¥1/M | ¥0.1/M | — | ¥4/M | **90% 折扣** |
| **国内多数** | — | — | — | — | **50-90% 折扣** |

## 二、Anthropic（Claude）计费模型详解

### 2.1 API 计费维度

从 Anthropic 官方 cookbook 中确认，API 返回的 usage 字段包含 **4 个维度**：

```python
usage.input_tokens              # 普通输入 token
usage.output_tokens             # 输出 token
usage.cache_creation_input_tokens  # 缓存写入 token（首次）
usage.cache_read_input_tokens      # 缓存读取 token（命中时）
```

### 2.2 各维度价格（Claude Sonnet 4 为例）

| 维度 | 价格 | 说明 |
|------|------|------|
| 输入 token | $3 / 1M tokens | 正常输入价格 |
| 缓存写入 | $3.75 / 1M tokens | 比正常输入贵 **25%**（1.25x） |
| 缓存读取 | $0.30 / 1M tokens | 比正常输入便宜 **90%**（0.1x） |
| 输出 token | $15 / 1M tokens | 输出价格是输入的 **5 倍** |

### 2.3 缓存机制

- **最小缓存长度**：Sonnet 1,024 tokens；Opus/Haiku 4,096 tokens
- **TTL**：默认 5 分钟（每次命中延长）；可选 1 小时 TTL（2x 基础输入价格）
- **断点限制**：最多 4 个显式断点
- **自动缓存**：推荐方式，只需在请求顶层加 `cache_control={"type": "ephemeral"}`

### 2.4 Claude Code 订阅（Max）的计费方式

Claude Code 通过 Max 订阅使用时，**不是按 token 精确计费的**，而是：

- **Max $100/月**：包含一定量的使用额度
- **Max $200/月**：更高额度
- 使用量通过 **"usage"** 衡量，综合考虑了输入、输出、缓存等因素
- 可以用 `/cost` 命令查看当前 session 的使用情况
- 超出额度后会降速（限流），而不是额外收费

**关键点**：Max 订阅下，缓存命中的 token 消耗的实际"成本"更低（因为 Provider 端计算成本更低），但对用户来说感知不明显——主要体现在 **同等额度下能做更多事情**。

## 三、OpenAI（Codex / GPT）计费模型详解

### 3.1 API 计费维度

OpenAI 的 API 同样区分 **3 个维度**：

| 维度 | GPT-4o 价格 | 说明 |
|------|------------|------|
| 输入 token | $2.50 / 1M tokens | 正常输入 |
| 缓存输入 | $1.25 / 1M tokens | 自动前缀缓存，**50% 折扣** |
| 输出 token | $10 / 1M tokens | 输出是输入的 **4 倍** |

### 3.2 缓存机制

- **自动前缀缓存**：无需显式标记，前缀匹配即可
- **最小缓存长度**：1,024 tokens
- **TTL**：约 5-10 分钟
- **无额外写入成本**：不像 Anthropic 的 1.25x 写入费用

### 3.3 Codex CLI / ChatGPT Plus 订阅

- **ChatGPT Plus**（$20/月）：包含 GPT-4o 使用，有速率限制
- **ChatGPT Pro**（$200/月）：更高额度
- **Codex CLI**：使用 API Key 计费，按 token 计费
- 订阅制下不区分缓存/非缓存，但在 API 层面仍会影响实际消耗

## 四、DeepSeek 计费模型

### 4.1 API 计费维度

DeepSeek 是国内最早公开缓存定价的 Provider：

| 维度 | DeepSeek-V3 价格 | 说明 |
|------|-----------------|------|
| 输入 token（缓存未命中） | ¥1 / 1M tokens | 正常输入 |
| 输入 token（缓存命中） | ¥0.1 / 1M tokens | **90% 折扣** |
| 输出 token | ¥4 / 1M tokens | 输出是输入的 **4 倍** |

### 4.2 缓存机制

- **自动前缀缓存**：与 OpenAI 类似
- **价格差**：缓存命中 vs 未命中 = **10 倍差价**
- 这就是你提到的国内 Provider 的典型定价模式

## 五、GLM（智谱）计费模型

### 5.1 API 计费方式

智谱的计费模型 **不区分缓存/非缓存**，按统一价格计费：

| 模型 | 输入价格 | 输出价格 |
|------|---------|---------|
| GLM-4-Plus | ¥50 / 1M tokens | ¥50 / 1M tokens |
| GLM-4-Flash | ¥0.1 / 1M tokens | ¥0.1 / 1M tokens |
| GLM-4-Long | ¥1 / 1M tokens | ¥1 / 1M tokens |

**关键点**：智谱的 API **不提供缓存折扣**，所有输入 token 统一价格。这意味着：
- 缓存命中对智谱用户 **没有价格优势**
- 压缩上下文对智谱用户 **是纯收益**（不涉及缓存损失）

### 5.2 套餐模式

智谱提供 **token 包** 套餐：
- 按量购买 token 包，用完为止
- 不区分输入/输出/缓存
- 统一 token 消耗

## 六、小米（MiMo）计费模型

### 6.1 API 计费方式

小米的 MiMo 模型通过小米云服务提供：

| 模型 | 输入价格 | 输出价格 | 说明 |
|------|---------|---------|------|
| MiMo-7B | ¥0.5 / 1M tokens | ¥2 / 1M tokens | 轻量模型 |
| MiMo-72B | ¥2 / 1M tokens | ¥8 / 1M tokens | 大模型 |

**关键点**：
- 小米的 API 目前 **不提供缓存折扣**
- 统一按输入/输出分别计费
- 不存在缓存命中率的问题

## 七、订阅制 vs 按量计费：对压缩工具的影响

### 7.1 两种计费模式对比

| 维度 | 订阅制（Max/Pro） | 按量计费（API） |
|------|----------------|---------------|
| 计费方式 | 固定月费，含使用额度 | 按 token 精确计费 |
| 缓存是否影响账单 | **间接影响**（同等额度做更多事） | **直接影响**（缓存省钱） |
| 压缩工具价值 | 延长使用额度 | 直接减少账单 |
| 缓存价格差感知 | 弱 | 强 |

### 7.2 各场景下的压缩工具价值

| 场景 | 缓存折扣 | 压缩工具价值 | 推荐 |
|------|---------|------------|------|
| **Anthropic API 按量** | 90% | 缓存影响大，需谨慎选工具 | lean-ctx（缓存安全） |
| **OpenAI API 按量** | 50% | 缓存影响中等 | RTK / lean-ctx |
| **DeepSeek API 按量** | 90% | 缓存影响大，需谨慎 | lean-ctx（缓存安全） |
| **智谱 API 按量** | 无 | 纯收益，无缓存顾虑 | 任何工具都可以 |
| **小米 API 按量** | 无 | 纯收益，无缓存顾虑 | 任何工具都可以 |
| **Claude Max 订阅** | 间接 | 延长额度，缓存影响弱 | RTK / Headroom 都可以 |
| **ChatGPT Plus 订阅** | 间接 | 延长额度，缓存影响弱 | RTK / Headroom 都可以 |

## 八、给你的建议

### 8.1 如果你用的是国内 Provider（智谱/小米等，无缓存折扣）

**任何压缩工具都是纯收益**。不需要担心缓存命中率问题。
- 推荐：RTK + lean-ctx，或者 Headroom 也可以

### 8.2 如果你用的是 DeepSeek（有 10 倍缓存差价）

**需要谨慎**。压缩对话历史可能导致缓存失效。
- 推荐：RTK + lean-ctx 工具模式（只压缩工具输出）
- 避免：Headroom proxy 模式（压缩全部内容）

### 8.3 如果你用的是 Anthropic Claude（有 10 倍缓存差价）

**需要谨慎**。但 Claude 的自动缓存机制比较智能。
- 推荐：lean-ctx（确定性压缩，缓存安全）
- 可以用：RTK（零缓存风险）

### 8.4 如果你用的是 Claude Max 订阅

**不太需要担心缓存问题**。压缩工具主要是延长使用额度。
- 推荐：RTK（最简单）或 Headroom（更全面）
