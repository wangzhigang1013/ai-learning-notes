# 代码质量规范

## 写代码前
- 先看项目里已有的模式和风格，跟着走
- 不确定方案时先问用户，不要猜
- 不要过度工程化：够用就行，不加不需要的抽象层

## 写代码时
- 不删除已有代码/注释/格式，除非确实必要
- 每次改动尽量小、可测试
- 不留临时修复（TODO、FIXME 必须有明确计划）
- 错误处理要具体，不要空 catch 或 catch-all

## 写完后
- 跑相关测试（优先单个测试，不跑全量）
- commit message 说清楚改了什么和为什么

## 安全
- 不硬编码密钥/token/密码，用环境变量
- 用户输入必须校验
- 最小权限原则：不给不需要的权限
